## Fork source notices

Root [NOTICE](../NOTICE) identifies vpn0wn as a modified WireGuard Android fork and credits novakin and project contributors without replacing original ownership or component terms. The offline credits source now copies it verbatim as its first whole notice, preserving the complete prior payload. Source placement alone does not establish actual APK inclusion or distribution acceptance.

Comparison with pinned Android upstream `e7b3a3c118836e112620b1302a8ba1873ad4daac` identifies 120 directly inherited changed/renamed Apache-header files. Their leading comments now state `Modified for vpn0wn.` while retaining original copyright, SPDX and complete license bytes. The 24 unchanged inherited files and seven verified deleted carriers receive no edits. Three traced extractions receive the same change notice: `LogLineParser.kt` retains the original WireGuard LLC header from `LogViewerActivity.kt`; `tunnelhandles.go` and `uapiserver/server.go` restore the exact Jason A. Donenfeld header from `api-android.go`. The native extraction notices preserve the source carrier's attribution; they do not assert ownership of every added line or decide the protectability of short declarations or loops.

A separate comparison with the same pinned upstream identifies 43 additional changed inherited text files without per-file Apache SPDX/copyright headers: 36 string-resource XML files and seven build/config files (`.gitignore`, `build.gradle.kts`, `gradle.properties`, `gradle/libs.versions.toml`, `settings.gradle.kts`, `tunnel/build.gradle.kts` and `ui/build.gradle.kts`). Their leading syntax-safe comments state `Modified for vpn0wn.`; XML keeps its original declaration first and the notice immediately below it. Removing only that inserted comment recovers every original byte; parsed resource trees, build bodies and configuration semantics are unchanged. These factual modification notices add no copyright, SPDX declaration or relicense and make no protectability claim. [Translation import guidance](development.md#translation-resource-imports) preserves the XML notice and fork resources after upstream or manual imports.

These are bounded notice slices, not a complete provenance assessment. Header detection and explicit package/path mapping do not certify every file's provenance. Other newly introduced or rewritten carriers, including `LogBuffer`, `LogcatStream` and the `AppDataExporterPreference` export-pattern lineage, remain outside automatic inherited-file admission. Generated `gradle-wrapper.properties`, the official wrapper JAR and the 11 replaced launcher/round/TV PNGs are excluded from the 43-file text slice; their generation owners and component provenance need separate handling. The existing README already prominently identifies the fork and its changes. Existing [#71](https://github.com/novakin/vpn0wn-android/issues/71) tracks the remaining source and distribution boundary.

The native overlay helper quotes pinned MIT WireGuard source and emits changed MIT copies. Preserve their original copyright and full permission notice with the applicable source distribution; the helper's Apache declaration does not relicense its quoted material or output. No generated MIT modification labels are added as an Apache requirement. Go/runtime BSD patch material, external gitlinks, provisioning MIT, fonts and component notices retain their existing terms. The [wrapper regeneration workflow](development.md#gradle-981-compatibility-and-upgrade-notes) reapplies the separate Unix-launcher comment after the two official passes; wrapper binaries remain unchanged.
