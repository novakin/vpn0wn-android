# Software licenses and credits

Last updated: 2026-10-10 (Europe/Paris).

Settings → About → Licenses & credits opens a private native activity with selectable, scrollable offline text. The version row opens the same screen, identifies vpn0wn and keeps its actual backend-version summary. The upstream donation preference, URL, Google Play-specific dialog and donation strings in all 29 affected resource sets are removed. English/French navigation strings use normal English fallback elsewhere. The [Android artwork adoption](ui-redesign-roadmap.md#android-brand-asset-adoption--2026-10-10) adds the complete Sora notice for the outlined logo; installed package/source identity, tools coexistence and complete old/new-app transfer acceptance remain separate [#71](https://github.com/novakin/vpn0wn-android/issues/71) work. The [upstream app updater is retired](operations.md#app-updates) in a separate source-preparation slice; its removal introduced no dependency or notice change. [Operations](operations.md#app-data-transfer) owns implemented legacy-ID transfer preparation and its limits.

The payload is [credits.txt](../ui/src/main/assets/licenses/credits.txt), in the existing Android main asset directory. Its bundle normalizes line endings and trailing spaces while preserving complete license wording; original copies remain unchanged. Full font notice assets remain beside it. Source [COPYING](../COPYING), upstream copyright and externally owned submodules are unchanged. The activity reads the local asset off Main, reports an I/O failure and retains native Back/inset handling. No browser or preference write is required.

Each top-level notice appears in a separate selectable LTR text view, preserving the payload's complete text, whitespace and order. Android limits the text supplied by one accessibility node to 100,000 UTF-16 characters; the 28 current notices are each smaller, with a largest notice of 35,350 characters. The added Sora notice follows the original 27 unchanged notices. Select all and copying cover the current notice rather than the entire bundle. `LicensesActivityTest` checks actual accessibility-node text against every complete rendered notice and the concatenated original payload; refreshes must retain this size boundary or split an oversized notice without changing its text.

Keyboard-focused notices retain their normal text contrast and display a cyan outline behind the text, with 4dp clearance. This local focused background prevents Android's default foreground focus overlay from dimming selectable text; touch selection and the global theme remain intact.

The per-notice repair described above preserves those verified asset bytes, and its JVM regression checks complete framework accessibility-node text. Authorized repaired debug assembly and Detekt passed on 2026-10-10 from the same base revision with the uncommitted rendering/test/documentation repair; repaired APK SHA256 `2212d8ebcb236c2856e015833ac1c1e4c9c5f8d8b899441c84771f9cc1386c61`. This is a scoped debug-artifact audit, not complete distribution acceptance. Before distribution, inspect actual release/googleplay and shrunk contents, check remaining file-specific/third-party and toolchain-runtime notices including DataStore's native contribution, resolve any applicable ambiguous source declaration, and supply corresponding source/relinking material required by the actual copyleft binaries.
