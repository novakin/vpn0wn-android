## Preserved source and compatibility contract

- [Interface configuration](https://github.com/novakin/vpn0wn-android/blob/3d29b73e0a891d6a9b3a689578c982ccfae768de/tunnel/src/main/java/com/vpn0wn/config/Interface.java#L408) normalizes zero to absent and serializes only a present explicit ListenPort. Explicit nonzero remains configured intent. A fresh omitted/imported-zero activation permits native automatic selection; it guarantees neither the same nor a different port across activations.
- The [Android bind](https://github.com/novakin/vpn0wn-android/blob/3d29b73e0a891d6a9b3a689578c982ccfae768de/tunnel/tools/libwg-go/androidbind/bind.go#L58) protects new sockets before readiness and tracks warm-up eligibility from explicit UAPI intent. The [native overlay](https://github.com/novakin/vpn0wn-android/blob/3d29b73e0a891d6a9b3a689578c982ccfae768de/tunnel/tools/libwg-go/cmd/wireguard-overlay/main.go#L162) first opens automatic intent with zero, then retains the selected runtime `netc.port` for rebind. It publishes the actual port only after successful setup; failed replacement supplies no hidden port fallback or health success.
- [Retained rebind](https://github.com/novakin/vpn0wn-android/blob/3d29b73e0a891d6a9b3a689578c982ccfae768de/tunnel/tools/libwg-go/cmd/wireguard-overlay/main.go#L235) replaces the [Device's shared bind](https://github.com/novakin/vpn0wn-android/blob/3d29b73e0a891d6a9b3a689578c982ccfae768de/tunnel/tools/libwg-go/api-android.go#L95). Socket replacement already affects all peers. Port rotation can additionally change interface-wide UDP/NAT/firewall flow state and disrupt healthy peers or violate fixed-port requirements. A local ListenPort change does not guarantee a different public NAT port.
- Existing [backend admission](https://github.com/novakin/vpn0wn-android/blob/3d29b73e0a891d6a9b3a689578c982ccfae768de/tunnel/src/main/java/com/vpn0wn/android/backend/GoBackend.java#L321) and [manager episode validation](https://github.com/novakin/vpn0wn-android/blob/3d29b73e0a891d6a9b3a689578c982ccfae768de/ui/src/main/java/com/vpn0wn/android/model/TunnelManager.kt#L717) preserve the [selected #73 finite controller](../backend-contracts.md#proposed-bounded-automatic-recovery--73), profiles and peer Endpoint/configuration. Its shared-socket effects, finite accounting and cancellation/uncertain-settlement limits remain. The [recovery bootstrap boundary](../operations.md#recovery-and-bootstrap-policy--73-draft) stays fail closed; unknown policy grants no DNS exception. Startup resolution is unchanged.

## Rationale, alternatives and remaining work

The current records provide no controlled port comparison attributing a failure to the local port, and no justified candidate is selected. Adopting rotation now would add interface-wide flow changes and potential disruption without that target. Retaining current behavior is proportionate to the evidence and preserves fixed/automatic ListenPort, ordinary WireGuard packets, saved profiles, remote Endpoint ports and existing recovery/bootstrap owners.

A later assessment may reconsider a reproducible diagnosed failure and a separately approved candidate under #77's existing explicit-port opt-in, all-peer, bounded-work, packet and rollback criteria. That is a possible future efficacy investigation, not evidence required to complete this no-candidate assessment now. No new trigger, packet sender, scheduler, resolver exception or runtime policy is introduced.

Optional AmneziaWG remains the separate unselected [#76](https://github.com/novakin/vpn0wn-android/issues/76) decision; it is not a universal prerequisite for ordinary-WireGuard assessment. Existing mode/packet compatibility must not be confused with port rotation. Broader #61/#73/#75/#76 and parent #72 remain open.
