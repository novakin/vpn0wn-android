## APK accessibility linking diagnostic

The maintainer supplied an `E hiddenapi` screenshot showing `AccessibilityNodeInfo.getSelection()` denied "using linking". Read-only source/APK inspection located the reference in AndroidX Core 1.18.0's `AccessibilityNodeInfoCompat.getSelection()`, guarded by `BuildCompat.isAtLeastB_1()` (SDK at least 36 with `SDK_INT_FULL` at least `3600001`). The retained `f4a4b147` APK and final palette APK from `cac38793` contain the same method bytecode. Tunnl source has no direct call to that platform method.

[The Android API reference](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo#getSelection()) dates the public method to API 36.1. [Android 16 ART source](https://android.googlesource.com/platform/art/+/refs/tags/android-16.0.0_r1/runtime/hidden_api.cc#420) explains that linking warnings can arise during static bytecode analysis/compilation for code never executed. The screenshot alone establishes neither a crash nor broken accessibility. Its precise trigger, same-PID exception correlation and installed image's full SDK/flag state were not verified. No dependency or app repair follows from that line alone; actual TalkBack traversal, actions and spoken confirmation remain acceptance gates.
