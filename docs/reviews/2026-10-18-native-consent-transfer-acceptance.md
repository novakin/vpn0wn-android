## Upgrade and transfer trials

The finite cohort uses the retained same-signer legacy baseline A (`8ab6a8062d66180c1c0b327fd51346e27ba3fa4b`), legacy exporter B (`e4efaea0d424e279d04ceee5dee3e8e396115d33`) and new-ID importer C built from normal production sources without an injected harness. A and B have versionCode 519; the intended code replacement is equal-version A→B→A→B. C has a separate package and sandbox. Its APK SHA256 is `5e4bbc8f2a27dcd5bd6a243711e28a5bcb17e360db248c18784c2f0c9a822a06`. C's ABI-targeted debug build uses `android.injected.build.abi=x86_64`; its actual manifest declares `android:testOnly="true"`. It requires Android's test-install flag and is not a release or ordinary manual-install artifact.

The owned API-36 x86_64 emulator uses Google APIs image revision 7. Fresh local SDK metadata was inspected; no upstream image-archive integrity or physical-device equivalence is claimed. Synthetic profiles have no peers/endpoints and remain DOWN. No VPN connectivity is requested.

The first cohort installed A successfully, then host admission rejected CRLF `firstInstallTime` parsing. No seed import or upgrade ran. The consumed install was not retried. The owned emulator stopped with all five preservation checks true; installed A data and evidence were retained.

Fresh A2 corrected only CRLF parsing and cohort bindings. Independent ultra review, 33 injected Python controls, five injected PowerShell cases and syntax checks passed. Actual baseline installation and native Settings/DocumentsUI seed import then passed. Stopped capture retained preferences and both synthetic profiles, but rejected the first profile's `0660` mode because the harness required `0600`. B was not installed. The failed capture and all original inputs remain retained. The owned emulator stopped with all five preservation checks true.

`0660` alone is not an app-private file defect: [Android's `MODE_PRIVATE` contract](https://developer.android.com/reference/android/content/Context#MODE_PRIVATE) defines app-private access, and [Android 16 ContextImpl](https://android.googlesource.com/platform/frameworks/base/+/android-16.0.0_r1/core/java/android/app/ContextImpl.java) starts its file permissions with owner/group read-write bits. `FileConfigStore` uses `Context.MODE_PRIVATE`. All three audited manifests omit `sharedUserId`. The proposed harness correction admits only `0600` or `0660` with the verified package's own UID and primary GID, while preserving exact observed modes across every comparison. It does not chmod files or establish acceptance before execution.

The original and A2 trials establish no existing-installation upgrade, populated-destination transfer, rollback or complete finite-cohort success.

Fresh A3 admitted only `0600`/`0660` with the freshly verified installed UID and matching primary UID/GID. Exact mode/byte comparison stayed intact; 45 Python and five PowerShell injected controls plus independent ultra source/binding review passed. Native baseline installation, seed import, stopped capture, A→B update, cold B reopening and actual B export/collection then passed. The upgrade preserved UID, data directory, first-install time and stopped configuration/preference bytes and modes. Export collection checked the actual ZIP, MediaStore identity/owner/size/hash and typed synthetic content.

C installation stopped with Android's `INSTALL_FAILED_TEST_ONLY`, because the reviewed helper omitted `-t`. C did not install; no populated-destination import, rollback or final finite cleanup ran. The helper stopped at that first failure and gracefully stopped its owned emulator. All five stop/preservation checks passed; B, private data, owned synthetic outputs and failure evidence remain retained. A prospective fresh cohort adds the test flag only for this exact C artifact, with separately reviewed bindings; no signature/version bypass or new APK build follows from that preparation.

Earlier [cross-app transfer acceptance](2026-10-11-cross-app-transfer-acceptance.md) retains its original artifacts and scope. Increasing-version/release migration, process-death/power-loss atomicity, credential transfer, real tile membership, physical output and complete #71 acceptance remain open.
