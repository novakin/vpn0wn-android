## Failed preferences update settlement — #271

The shared `createPreferencesDataStore` owner retains the existing default AndroidX provider, preferences serializer, path and keys. Its #270 disk-scope guard and the #271 failed-update settlement have different responsibilities. The latter is implemented at the shared owner; final-head CI and delivery belong to its PR.

Pinned DataStore publishes its cache before final provider commit. An injected failure after that publication can therefore expose an uncommitted value to recovery code. The [default-provider regression](qa-test-plan.md#failed-preferences-commit-controls--271) demonstrates the resulting skipped encrypted-credential restoration during server removal, with unchanged original metadata bytes and correct unrelated-server preservation.

The owner serializes each public update and its failure settlement through one owner mutex. Waiting cancellation before admission does not submit an update. A unique owner context marker lets nested calls reach AndroidX's existing nested-update rejection instead of reacquiring the wrapper mutex; different stores keep separate ownership. A failed storage write scope advances its existing coordinator version so the prematurely published cache must be revalidated.

After an admitted update reports failure, the owner holds admission while a raw no-op update settles previously queued actor work, then reads through the raw DataStore to revalidate against disk. Settlement survives caller cancellation but remains a child of the actual DataStore owner: owner cancellation interrupts cleanup, including a pending actor acknowledgement, so shutdown can finish. This also handles caller cancellation returning before its actor finishes. The original failure is rethrown; a distinct cleanup failure is suppressed on it and leaves reconciliation incomplete. This is not an automatic retry of the requested mutation. A canceled/closed DataStore owner cannot be revived by cleanup.

Coroutine debug stack recovery can copy exceptions. Failure type, message and original cause remain observable, with cleanup failures reachable through that exception chain; top-level object identity is not a portable coroutine-boundary guarantee. Earlier optimistic emissions cannot be retracted, and existing collector delivery remains asynchronous. This does not establish instantaneous observer correction, filesystem atomicity, power-loss protection or successful recovery when cleanup itself fails. Existing store ownership/identity checks still govern credential restoration and remote-outcome journals. No schema, application identity or migration is introduced.

## WireGuard configuration and tunnel state

Configuration loads remain outside the mutation mutex. `TunnelManager.getTunnelConfig` captures the managed model object, current name and model-owned config generation before I/O; publication requires the same current ownership/name/generation. A later committed cache wins over an old read. Renaming without a current cache retries the load under the current name; rename-away/back still invalidates the captured generation. Deleted or same-name-replaced model objects are rejected before publication. This adds no reentrant mutation-lock wait and leaves admitted save/rollback and cancellation reconciliation unchanged. [#211](https://github.com/novakin/vpn0wn-android/issues/211) and [its focused QA](qa-test-plan.md#config-read-publication-controls--211) own the regression and verification scope.

The maintainer [selected optional AmneziaWG on 2026-10-19](https://github.com/novakin/vpn0wn-android/issues/76#issuecomment-6259581090). The [historical engine assessment](reviews/2026-10-09-amneziawg-engine-assessment.md) retains its source-only scope. The following implementation is in progress under [#76](https://github.com/novakin/vpn0wn-android/issues/76); it is not artifact/device/interoperability acceptance.

### Optional AmneziaWG configuration and native ownership — #76

The selected engine is official `github.com/amnezia-vpn/amneziawg-go/v3` `v3.1.20260828` (`b5928efb6ca19f0153958460c3d141f04abc5c2e`). Ordinary profiles retain the existing WireGuard engine and wire format. Both device implementations share one Go runtime, the existing JNI handle/query/UAPI owner and the protected socket owner. The typed AWG bind bridge passes configured I/J packets unchanged and never invokes the ordinary WireGuard initiation detector or its one-byte warm-up. The native initiation owner explicitly marks its packet train; the bridge sends its I/J prefix on one captured protected socket generation, rechecks service/generation, then sends the final initiation. Generic transport batching does not infer packet type or split its final packet. Cookies remain enabled when `DisableCookies` is absent/false. Engine selection does not establish DPI, throughput or energy improvement.

`Interface` retains immutable `AmneziaSettings`. An admitted AWG attribute selects AWG; `Protocol = AmneziaWG` also selects it when all extensions are absent. Export/save records explicit intent as `# vpn0wn:protocol=AmneziaWG` inside `[Interface]`, so other clients can ignore the comment without rejecting a new protocol key. This parser recognizes that exact marker before removing ordinary comments. An explicit `Protocol = WireGuard` combined with AWG attributes/intent is rejected. Ordinary WireGuard exports gain no marker. The existing editor proxy retains immutable parsed settings and Parcelable retains explicit field/value presence while existing fields remain editable. Final interface resolution checks packet sizes against the actual edited MTU; incomplete unrelated drafts remain parcelable. This slice adds no dedicated per-AWG-field controls.

The config owner preserves each admitted interface field's explicit presence and trimmed value, including zeros, plus AWG peer `PersistentKeepalive` scalar/range text. Fields are `Jc/Jmin/Jmax`, `I1–I5`, `S1–S4`, `H1–H4`, `HeaderProtectionKey`, `ContentPaddingAddition`, `RekeyAfterTime`, `RekeyTimeout`, `RejectAfterTime`, `KeepaliveTimeout`, `MaxHandshakeAttempts`, `RandomTrailers` and `DisableCookies`. Unknown fields and contradictory duplicates fail before native activation. The header-protection key is Base64 in profiles and hex in UAPI; failure diagnostics identify its field without retaining the rejected secret. Native `IpcGet` remains statistics/runtime output, not the lossless profile store.

The [selected-Network hostname path](#selected-network-hostname-recovery--7374) retains that same immutable interface and peer keepalive text, including explicit zero and ranges, when constructing the numeric runtime copy. Saved hostname/profile text stays unchanged. Both native devices implement the shared recovery handle contract with numeric replacement endpoint and current-generation admission; engine selection does not bypass the existing exhausted-episode, old-endpoint, port or cancellation guards. [Combined-source controls](qa-test-plan.md#optional-amneziawg-controls--76) pass focused JVM/static, host race/JNI and four-ABI artifact checks after integration with PR #300. Earlier separate-engine results retain their own scope; final integrated review/CI and installed API24 lifecycle acceptance remain pending.

Numeric ranges use ordered unsigned 32-bit endpoints. The full `0–4294967295` interval is rejected because the selected engine's inclusive random-bound addition wraps. `Jc` is a scalar at most 128; J sizes are scalar UDP payload lengths at most 65,507, with minimum no greater than maximum. Configured J/I packets may allocate at most 1 MiB per initiation, preventing the engine's unbounded count/allocation loop from exhausting mobile memory. These are app admission limits, not claims about all AWG implementations. S prefixes plus their message overhead must fit that same IPv4/IPv6-compatible UDP ceiling; S4 includes configured/default-1280 MTU and ordinary padding allowance. Nonzero header protection requires all S prefixes at least 12. Effective H ranges, including defaults 1/2/3/4, must not overlap. `ContentPaddingAddition` must fit a signed 32-bit native integer before the engine clamps it to the packet window. `RejectAfterTime` must fit the native three-times key-expiry duration and `MaxHandshakeAttempts` leaves room for the native counter's two extra attempts.

CPS accepts complete adjacent `<b HEX>` (optional lowercase `0x`), `<t>`, `<r N>`, `<rc N>`, `<rd N>`, `<d>`, `<ds>` and `<dz N>` tags. Each I packet is at most 65,507 bytes. Data tags use the engine's empty I-packet input; extra arguments, outside text, negative/overflow lengths, malformed hex and unknown tags are rejected rather than silently discarded. Empty I1–I5 values remain explicit empty chains through full configuration import/export; the narrow empty-field admission does not relax ordinary WireGuard attributes. Boolean admission is `true`, `false`, `0` or `1`; cookie disabling is an explicit opt-out that bypasses the selected engine's under-load MAC2/challenge/source limiter.

AWG activation uses the userspace engine only. Kernel UP/TOGGLE rejects an AWG config before root observation, tool installation or an existing tunnel transition; an explicit DOWN remains available. Standard WireGuard kernel tools and VPS provisioning remain unchanged. No AWG server deployment is added. An exact-source AWG overlay refreshes S4 after a blocked TUN read and relocates payload only if its offset changed, preventing the initial read's pre-configuration padding from losing the first data packet. Existing protected startup, captured transport ownership, retained-session rebind, exhausted-cycle recovery, admitted queries and teardown apply to both native devices. [Host/JVM/ABI evidence and remaining API24/installed gates](qa-test-plan.md#optional-amneziawg-controls--76) retain their separate scopes. #76 and parent #72 remain open.

The existing [Config](../tunnel/src/main/java/com/vpn0wn/config/Config.java), Interface, Peer and endpoint/address types own parse/serialize behavior. Preserve repeated list fields, multi-peer profiles, IPv6 endpoint syntax and other supported WireGuard fields. Generated provisioning profiles must pass these same parsers/import paths.

The native tunnel handle owns a standard Unix listener and accepted clients through `uapiserver.Server`. `Listen` preserves `/data/data/<application-id>/cache/wireguard/<interface>.sock`, creates new directories privately and applies socket mode 0600 before serving. It refuses an active socket, bounds the local probe to one second and replaces a stale socket only after connection refusal and confirmation that the path is a socket. Access denial, unexpected probe errors and non-socket paths are not treated as stale success. Teardown closes/unlinks the listener, waits for admission to stop, closes remaining clients and waits for their `IpcHandle` handlers before closing the device. Startup failures follow the same ordering. Closing a client unblocks an idle or partial request holding the pinned IPC lock; it does not roll back admitted settings. The Android owner replaces upstream queued acceptance, file duplication and deletion-watcher goroutines; unlinking the socket externally does not terminate the native device. Failed initial settings close the complete owned device. Current userspace source passes `GoBackend`'s exact `VpnService` and originating activation thread to JNI. The Android-owned native bind opens a fresh `StdNetBind` generation, protects every available IPv4/IPv6 socket inside `Open` at creation/rebind, then publishes it for sends. The version/match-checked overlay guards unavailable-family descriptors with `-1, syscall.EINVAL`; at least one real descriptor must be protected. Protection failure closes the unpublished sockets and fails activation/rebind. Cookie/control sends share this readiness boundary. The native context attaches/detaches callback workers; startup callbacks also check the originating thread's interrupt flag. After startup, callbacks check service lifetime only; an interrupted later Java caller must not permanently poison the shared activation context. Java operation boundaries own that caller's cancellation. Expected liveness/interruption exceptions and unexpected Java throwables retain their identity when JNI rethrows them on startup, the next native query, rebind or shutdown.

Warm-up eligibility comes from explicit UAPI ListenPort intent: nonzero enables it; absent/zero disables it, including later automatic reopens. One one-byte zero datagram attempt precedes each outgoing type-1 initiation on the same captured generation and Endpoint. Responses, cookies, keepalives and data get no extra packet. Expected warm-up I/O failure still permits the ordinary initiation; cancellation, descriptor closure and unexpected errors propagate. Recheck service/generation after potentially blocking warm-up before sending the initiation. WireGuard owns retry/rekey timing; add no sleep, acknowledgment, retry worker, timer or wake lock. The narrow pinned-source build overlay preserves the requested port on failed bind setup and closes bind/route-listener ownership on mark failure; cached upstream source is not patched and persisted profiles are unchanged; a cold build may download the validated module.

Shutdown marks the bind terminal and closes sockets to release blocked sends, stops/drains UAPI clients, closes the device and only then releases JNI references. The handle table admits reads without waiting under its lock and removes a closing handle before cancellation. Teardown cancels bind/UAPI I/O before draining admitted queries, then closes the device and releases JNI references. IDs increase without reuse within the native process, so a delayed lookup cannot acquire a replacement context; exhausting nonnegative 32-bit IDs fails startup. Java snapshots the tunnel/handle under its state lock, queries outside that lock and discards a result after identity changes. Java clears owned tunnel state before native teardown and publishes DOWN/restores service acquisition in cleanup even if JNI rethrows a callback defect. Existing transition ownership, service identity, config serialization and kernel behavior remain intact. Native warm-up replaces the separate Java five-attempt/200 ms preflight loop and late ignored socket-protection calls. ### Eligible triggers and finite limits

Only a fresh, attributed native `EXHAUSTED` cycle for a configured peer in the captured active userspace `HandshakeSession`, with a known current numeric runtime endpoint, may qualify. Native admission must claim that exact still-exhausted cycle. Java event sequence is capture order, not a native cycle identity or failure count. Peers without a current numeric runtime endpoint, unknown attribution and kernel mode cannot trigger recovery. A peer with no saved Endpoint can qualify after learning a numeric endpoint natively; recovery does not write that endpoint into its profile. A qualifying peer's socket replacement affects every peer sharing the activation's transport.

`ATTEMPT`, retries, `SENT` and a single `SEND_FAILED` remain observations while WireGuard owns its retry timing. Authentication superseding the triggering cycle before admission suppresses it; authentication after admission requires conservative reconciliation. Idle silence, old handshake/statistics, screen off, wake, Doze exit and network changes alone never trigger replacement. Known deep Doze suppresses new admission without consuming a charge or creating a wake queue; unknown power/reachability remains unknown.

Selected engineering defaults, not measured optimums:

- At most **two conservatively charged transport attempts per native activation**, **one pending/in-flight request**, and **30 seconds between charged attempts**. The manager claims the request slot on Main before waiting for `operationLock`; competing peer triggers update bounded per-configured-peer episode evidence and drop without creating another waiter. A fresh early trigger is recorded as rate-limited and dropped without a queue or retry timer. The shared budget already bounds every peer.
- Reserve a charge before backend entry. Commit charged spacing from the actual backend-body entry time only after admitted or unknown settlement; delayed IO dispatch cannot shorten that spacing. Refund only an explicitly proven non-mutating refusal or a body that never entered; that refusal does not advance charged-attempt spacing. Track confirmed admissions, charged usage and unknown settlement separately.
- At most **four backend admission requests per activation**. A positively identified non-mutating busy result permits **one cancellable 1-second deferral for that trigger**. A second busy refusal gets no further deferral; obsolete, unavailable, cancelled, ambiguous and terminal-context outcomes get no retry.
- Ambiguous settlement or a terminal/unusable JNI context disables all further automatic requests for that activation, including fresh triggers. Ordinary admitted I/O failure remains charged; only a positively reusable context and a new qualifying native cycle may use remaining budget. An `IOException` or native `-EIO` alone proves neither reusability nor permission to retry.
- Only a fresh native activation refills the budget. Later authentication permits a genuinely new failure within remaining budget; no-op UP, view recreation, selection, wake, old events and network churn do not refill it.

### Admission, native claim and settlement

Extend existing manager/model/backend/native owners, with no setting, monitoring service, extra statistics polling, ping, wake lock or general scheduler. Manager admission captures the exact managed model, backend instance, active session, triggering peer, event sequence and monotonic time. A narrow expected-session backend entry point must compare that session **inside backend admission** before native lookup, while preserving the existing library rebind method. Capture exact service, activation and nonreused native handle under `stateLock`; the bind retains socket-generation ownership. Recheck captured identities after settlement; a stale trigger must never acquire a replacement activation of the same model.

The native primitive publishes EXHAUSTED after keepalive deletion, staged-packet flush and zero-key cleanup setup. Its timer/protocol owner atomically claims the exact still-eligible episode, rejecting delayed exhaustion A after a later cycle B and authenticated progress. IPC locking alone cannot serialize timer/send/authenticated-receive paths. ### Experimental password archive codec — #196

`VpsBackupArchive.encrypt/decrypt` encode the validated snapshot as bounded authenticated bytes, independently of the original installation or Keystore. This remains an experimental source candidate; the separate [private export integration](#private-encrypted-server-export-candidate--196) adds its first writer caller without freezing the format. The [scoped native record](reviews/2026-10-16-native-backup-codec-acceptance.md) establishes producer-artifact API24/API36 linkage, interoperability and named heap/cancellation controls. The initial API36 cold cohort fails the proposed 2,000 ms p95 target at 3044.284840 ms; a separate settled diagnostic passes only its conditioned scope. A separate fresh-boot diagnostic has p95 1660.850712 ms and retains its 6004.295886 ms maximum; it does not replace the initial failure. Overall cold-performance acceptance and writer-format freeze remain open, alongside physical/OEM, production UI and integration gates. No restore or distribution acceptance follows; #196 remains open.

The single candidate profile is Argon2id v1.3 with 19,456 KiB, two passes, one lane, a fresh 16-byte salt and a 32-byte derived AES key. Bouncy Castle's pinned lightweight byte API supplies the KDF on every supported API level; it registers no provider. Platform `AES/GCM/NoPadding` uses that key with a fresh 12-byte nonce and 128-bit tag, without selecting a provider. [The dependency decision](architecture.md#experimental-portable-backup-cryptography--196-2026-10-16) and [notice/provenance record](license-attribution.md#bouncy-castle-backup-kdf-notice) own the compatibility tradeoff. Current [OWASP password guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#password-hashing-algorithms), checked 2026-10-16, prefers the selected Argon2id minimum and marks PBKDF2-SHA1 legacy-only; the older 1.3-million-iteration proposal is not implemented. Android documents PBKDF2-SHA256 only from API 26; no minimum SDK bump or hand-written KDF bridges that gap.

The fixed 56-byte header consists of ASCII `VPN0WNBK` (offset 0, eight bytes); archive version, cipher suite, KDF and Argon2 version (offsets 8–11, one byte each, exactly `1`, `1`, `1`, `0x13`); memory KiB, passes and lanes (offsets 12, 16 and 20, unsigned big-endian 32-bit values exactly `19456`, `2`, `1`); salt (offset 24, 16 bytes); nonce (offset 40, 12 bytes); and ciphertext-plus-tag length (offset 52, unsigned big-endian 32-bit). Ciphertext immediately follows; its last 16 bytes are the GCM tag. All original header bytes are AAD. Unknown identifiers, non-exact costs, overflowed/mismatched lengths, truncation and trailing bytes are rejected before KDF allocation. Plaintext is at most 786,432 bytes; ciphertext including tag is 17–786,448 bytes; the complete archive is at most 786,504 bytes. Future file readers must enforce that cap during acquisition, even when provider size metadata lies; this byte-array codec does not acquire URI streams.

Plaintext explicitly serializes `ok`, `snapshotVersion`, `capturedAtUtc`, `interface`, `config`, `revokedCount` and `revoked`, preserving snapshot text and its existing parser/field/count/total bounds. `ProvisioningJson.encodeBackup` now owns this bounded serialization for the codec and restore client; the envelope, JSON schema, Argon2id costs and password rules are unchanged. JSON field order is not a canonicalization requirement. Invalid UTF-16/UTF-8 and serialization expansion beyond the cap fail without truncation. One bounded `doFinal` authenticates before plaintext reaches strict UTF-8 decoding or the existing snapshot validator. The existing Backend API exposes no effective-MTU readback. Current-tunnel config notifications refresh Detail without a new load; selection/view ownership guards reject stale callbacks and clear unavailable values. No profile or backend policy changes.

Home's `VPN connected` label retains the existing recent-handshake aggregate heuristic; it does not prove routing, leak protection or all-peer health. The right-hand Endpoint value is the first configured peer's hostname from the first tunnel presented as active, without DNS resolution or public-IP discovery; absent data displays `—`. Home `LAST HANDSHAKE` adds a localized relative-age phrase to the newest positive observed peer timestamp, preserves `--` when missing and clamps future timestamps to the existing `0s` formatter result. Detail keeps the compact age without the phrase. The configured header count and preserved `Vpn0wn` wordmark add no backend state or identity migration.

Quick Settings membership is a nullable confirmation in the existing settings DataStore, independent of `TileService` creation, destruction and listening. `QuickTileService.onTileAdded` and native request results `TILE_ADDED`/`TILE_ALREADY_ADDED` persist true; `onTileRemoved` persists false. Missing pre-repair confirmation remains unknown, not proven absence. Writes use the application scope and existing serialized DataStore transactions, so normal activity/service teardown does not cancel them; app-process reconstruction retains committed values. Abrupt process termination before a write commits, persistence failure and notifications Android has not delivered remain outside that guarantee. Expected persistence failures retain prior data and log a fixed category without inventing an absent confirmation.

`UserKnobs` owns a process-local removal revision. Each native Add request and add notification captures that revision before asynchronous confirmation work; actual removal advances it synchronously before its false write is launched. A true confirmation checks the captured revision inside the DataStore transaction and skips its write after any later removal. Native request results and service notifications use independent callback channels, so a late successful/already-added result must not reassert membership after a genuine removal, including after Settings destruction. A new add notification/request captures the current revision and remains eligible. Process termination discards old callbacks; the revision needs no persistence or settings-format migration, while committed membership remains durable.

Android 13+ Settings keeps its Add tile row hidden until membership loads, then hides confirmed membership and offers the native idempotent fallback for false or a loaded value without recorded confirmation. A view-lifecycle observer applies later confirmations and removals while Settings stays open; stopping/recreating its view releases and reloads observation. An unavailable read keeps setup hidden until a later lifecycle observation loads confirmation; it never writes absence. Request cancellation and reported native errors do not record membership; existing visible Snackbar/background Toast feedback remains. Android versions below 13 still omit the setup action. No platform inventory query, new service or tunnel/backend behavior is added. [#85](https://github.com/novakin/vpn0wn-android/issues/85) owns independent native inventory/reopening acceptance.

`ObservableTunnel.statistics` is a cache-only bindable getter; it starts no backend work. Existing Home, Detail and TV pollers use nullable `getStatisticsAsync`, routed through `TunnelManager.getTunnelStatistics`. A fresh snapshot from the current backend/session is reused without copying or retimestamping; `Statistics.isStale` remains true only after more than 900ms. Equivalent stale/missing readers share one manager-owned in-flight request for the same managed tunnel identity, generation, backend instance and name. Admission uses the existing mutation lock briefly; backend IO and reader waits run outside it.

Before publishing on Main, the manager checks caller/application liveness, request identity, managed membership, UP state, generation, name and backend identity. DOWN/TOGGLE, reconnect, admitted config/rename/delete work and backend switching invalidate affected sessions. Backend `onStateChange` advances an `AtomicLong` generation immediately on its callback thread, before queued Main reconciliation; even a rapid DOWN/UP pair cannot preserve the old cache. Cache reads reject a snapshot tagged with an earlier generation. TV clears and hides its transfer row when the result is unavailable.

Each reader owns its wait, not the shared request. Cancelling one reader preserves work needed by others; the last reader removes its request and cancels its shared read. Ordinary unavailable/obsolete sessions return null so still-active pollers can continue. A new request through an unmanaged tunnel retains `NotManagedException` rejection; an already-admitted read invalidated by deletion returns null. Owner invalidation is identified by its exact cancellation cause; genuine caller, application or backend cancellation propagates, as do backend failures and `Error`. Completed failures are not converted into obsolete success. Failed/cancelled requests can be retried. `runInterruptible` supports interruption of cooperative blocking Java work, not a guarantee that blocking JNI returns; native owners retain teardown responsibility.

These are the separately authorized [#48](https://github.com/novakin/vpn0wn-android/issues/48) source contracts. Its PR owns executed checks, review and delivery state. The [G2 investigation](reviews/2026-10-07-performance-source-investigation.md) preserves the original defect evidence. This source change establishes no physical VPN behavior or speed/battery gain.

Home selection stores managed tunnel identities, not numeric row positions. Saved names are recreation inputs only; restored views require a new destructive confirmation. Rename preserves inventory membership during store I/O and synchronously reindexes the same instance on Main under the manager's mutation lock. A confirmation captures current instances, updates observed warnings and is dismissed when a snapshot member leaves inventory or its owning view is destroyed. Only the current, showing dialog can admit its captured snapshot; a dismissed callback cannot consume a later confirmation's intent. A same-name replacement is never admitted through the stale instance. The manager identifies stale ownership with internal NotManagedException, preserving the prior IllegalStateException superclass/message; other unexpected runtime defects propagate through bulk deletion. Confirmed bulk deletion reuses the manager's serialized delete/rollback contract sequentially; cancellation stops remaining work after admitted settlement. Partial feedback reports observed removed/remaining snapshot members, and survivors remain selected. No persistence format, multi-peer/config parsing or backend transition policy changes. See [Home source proof and physical limits](development.md#home-selection-and-safe-delete-recovery--2026-10-07).

`FileConfigStore` preserves `.conf` names and wg-quick serialization. Its single app-owned instance serializes create/save/load/enumerate/rename/delete. Create/save write a unique private `.tmp` in the same directory, sync and close it, then atomically rename it to the target. Failed write/sync/rename reports IO failure and retains the prior profile; failed create publishes no profile. Rename rejects an existing destination without creating a marker. Temporary cleanup is attempted and failures log no profile payload. Process death can leave a private ignored `.tmp`; no automatic deletion of existing files or migration is performed. This does not establish directory durability under power loss or coordination with external writers/other store instances. See [architecture decision](architecture.md#local-profiles-commit-through-native-atomic-rename) and [focused evidence](development.md#atomic-local-profile-replacement--2026-10-06).

`VpsServerStore` keeps non-secret fleet metadata and nullable running observations through existing DataStore transactions. Legacy records without `running`, and malformed running types, remain usable with unknown health. Identity-checked status updates persist the new true/false/null observation; failure retains the previous observation with its original age. Corrupt-store warnings exclude payloads/parser causes. Protected SSH credential persistence remains separate.

`VpsDeployMapper` maps incomplete endpoint/CIDR to PROVISIONING. Its nullable presentation endpoint/listener retain known metadata without substituting the SSH host or the wizard's default UDP port. Blank endpoints and missing, nonnumeric or out-of-range listeners are unknown. Fleet, detail and user endpoint rows display `—` unless both endpoint and listener are known; the topology may still show a known endpoint host and the listener row may still show a known UDP port independently. `VpsDeployServer.endpointAddress` brackets bare IPv6 hosts once for complete display/copy as `[address]:port`; already bracketed IPv6, IPv4/hostname spelling and stored observations remain unchanged. This formatting performs no DNS resolution or address normalization. Compact native row ellipsis retains complete text/accessibility values, and endpoint Copy uses the complete formatted socket address. Unknown endpoints have no copy action. Missing provider/region labels display `—`; SSH user/host are connection identity and do not establish hosting provider/geographic region. Detect/status observations replace previous metadata, including empty values; stopped observations retain their actual metadata. The non-secret persisted schema and wizard's editable installation defaults remain unchanged.

Complete records need a positive, nonfuture sync timestamp at most 600 seconds old: running true maps ONLINE, false OFFLINE and null ATTENTION. Missing, future or older timestamps map ATTENTION regardless of old running evidence. Recent-sync and running health checks express separate facts; stale running health is unknown. ONLINE means recently observed interface presence, not a successful handshake, route, NAT, DNS or packet test. Peer ACTIVE also requires a recent status snapshot, running true and a nonfuture positive handshake at most 180 seconds old; unavailable counters render as an em dash.

UI presentation must use actual selected/view-owned data. Abbreviated keys remain display-only; copy/export/QR need the complete authorized payload. The manager publishes the resolved transition target before entering `TOGGLE`. A pending disconnect renders DOWN with its switch off and disabled; a pending connect renders CONNECTING with its switch on and disabled. Settlement clears the target, including failed-disconnect restoration to observed UP. State is updated before statistics-clear notifications so bindings cannot briefly classify a disconnect as connecting.

RX/TX bindings share one cached result for each `Statistics` snapshot. A fresh snapshot with unchanged counters publishes zero after the minimum sample interval; repeated reads of that same snapshot retain its result. Rapid snapshots accumulate traffic until that interval, counter rollback restarts the baseline, and absent statistics clears the baseline for reconnect. These are display calculations, not packet-health proof. See [regression and device evidence](development.md#phone-ui-and-throughput-follow-up--2026-10-06).
