## WireGuard configuration and tunnel state

Configuration loads remain outside the mutation mutex. `TunnelManager.getTunnelConfig` captures the managed model object, current name and model-owned config generation before I/O; publication requires the same current ownership/name/generation. A later committed cache wins over an old read. Renaming without a current cache retries the load under the current name; rename-away/back still invalidates the captured generation. Deleted or same-name-replaced model objects are rejected before publication. This adds no reentrant mutation-lock wait and leaves admitted save/rollback and cancellation reconciliation unchanged. [#211](https://github.com/novakin/vpn0wn-android/issues/211) and [its focused QA](qa-test-plan.md#config-read-publication-controls--211) own the regression and verification scope.

AmneziaWG is not accepted by the current parser/backends. The [2026-10-09 engine assessment](reviews/2026-10-09-amneziawg-engine-assessment.md) records the pinned official candidate, complete field/native/API 24/license matrix and proposed WG/AWG pre-initiation packet separation under [#76](https://github.com/novakin/vpn0wn-android/issues/76). Engine/field selection remains open; this assessment changes no accepted attributes, persistence, backend or packet behavior.

The existing [Config](../tunnel/src/main/java/com/vpn0wn/config/Config.java), Interface, Peer and endpoint/address types own parse/serialize behavior. Preserve repeated list fields, multi-peer profiles, IPv6 endpoint syntax and other supported WireGuard fields. Generated provisioning profiles must pass these same parsers/import paths.

| Section | Accepted attributes |
| --- | --- |
| Interface | `Address`, `DNS`, `ExcludedApplications`, `IncludedApplications`, `ListenPort`, `MTU`, `PrivateKey`. |
| Peer | `AllowedIPs`, `Endpoint`, `PersistentKeepalive`, `PresharedKey`, `PublicKey`. |

Private/public key requirements and value validation belong to those parsers. Peer Endpoint is optional; IPv6 endpoint literals use `[address]:port`. Unknown attributes, including wg-quick hooks and `SaveConfig`, are rejected. DNS serializes when servers or search domains exist, preserving domain-only and mixed IPv4/IPv6/search-domain profiles across save/export round trips. Existing ordering groups servers before search domains; repeated entries retain the parser's set semantics. Explicit prefixes must be 0–32 for IPv4 or 0–128 for IPv6; negative or oversized values throw ParseException, wrapped with the existing Interface Address/Peer AllowedIPs location by config parsing. Omitted prefixes remain host masks (32/128). #16 merged these repairs in PR #26; no file migration or automatic rewrite is performed.

`InetEndpoint.parse` removes URI host brackets before numeric validation. Successful numeric IPv6 endpoints store the bare address, preserving its spelling and any accepted scope suffix; serialization restores `[address]:port`. If numeric validation fails, the original URI host remains on the existing unresolved path, including rejected scoped addresses. [#141](https://github.com/novakin/vpn0wn-android/issues/141) repairs the Android bracket-rejection boundary at this parser owner without changing ports, DNS resolution policy or saved profiles. Native observation family detection still requires a numeric address and rejects malformed callback endpoints; new Android IPv6 transport acceptance remains separate from this source repair.

Backend state uses `DOWN`, `UP` and `TOGGLE`. `TunnelManager` uses TOGGLE as an in-progress observable transition; it is not proof of an active VPN. Its coroutine mutex serializes mutations and state snapshots. Waiting admission remains cancellable; admitted operations finish backend/store/model reconciliation before propagating caller cancellation. Explicit DOWN queues behind earlier UP/TOGGLE, including requests not yet admitted. Deleted model references cannot reactivate a tunnel. Delete disconnects the observed backend before removing persistence/model ownership; failed deletion attempts restoration. Failed config saves retain the cached/persisted profile and attempt runtime restoration; recovery errors remain attached to the failure.

Kernel interfaces can remain UP after app/process recreation even though the new `WgQuickBackend` has no cached running configuration. The manager supplies the managed profile for an observed-UP kernel DOWN, including toggle, active delete, rename and backend switching, so the existing wg-quick cleanup can run. Configuration remains model/store-owned; no raw interface removal substitutes for cleanup. Userspace DOWN remains independent of configuration loading, and already-DOWN kernel profiles require no configuration read merely for no-op shutdown or deletion. [#109](https://github.com/novakin/vpn0wn-android/issues/109) owns the discovered contract mismatch; [PR #110](https://github.com/novakin/vpn0wn-android/pull/110) owns delivery and scoped recreated-backend/rooted-device acceptance.

Initialization settles inventory waiters on failure/cancellation and retries failed loads. Inventory becomes available before automatic restoration; restoration children stay attached to their caller. Application backend initialization also settles cancellation instead of publishing fallback success. Backend notifications reconcile current observed state under the same manager lock; they preserve persisted restoration intent after spontaneous service loss. Explicit manager requests own changes to that intent. Detail config/statistics completions require the same binding and selected tunnel; destroyed views cancel their jobs. These scoped repairs merged in PR #25; complete kernel transition serialization merged in PR #27 under #15 as described below.

Backend switching drains prior transitions and disconnects tunnels under the manager admission lock before changing the preference. After that commit, queued mutations are rejected until restart; failed/cancelled restart restores the previous preference and releases the reservation. Shutdown failure can leave already-stopped tunnels down with their profiles intact, but restores usable controls. Preference rollback failure remains visible and keeps the reservation; it is not successful switching.

`GoBackend` manages Android VpnService and userspace/native activation; `WgQuickBackend` manages root/kernel commands. Preserve required permission/service setup and explicit ordering. A stale/destroyed service must not be reused; teardown cannot block the main thread waiting for long activation.

The native tunnel handle owns a standard Unix listener and accepted clients through `uapiserver.Server`. `Listen` preserves `/data/data/<application-id>/cache/wireguard/<interface>.sock`, creates new directories privately and applies socket mode 0600 before serving. It refuses an active socket, bounds the local probe to one second and replaces a stale socket only after connection refusal and confirmation that the path is a socket. Access denial, unexpected probe errors and non-socket paths are not treated as stale success. Teardown closes/unlinks the listener, waits for admission to stop, closes remaining clients and waits for their `IpcHandle` handlers before closing the device. Startup failures follow the same ordering. Closing a client unblocks an idle or partial request holding the pinned IPC lock; it does not roll back admitted settings. The Android owner replaces upstream queued acceptance, file duplication and deletion-watcher goroutines; unlinking the socket externally does not terminate the native device. Failed initial settings close the complete owned device. These source controls do not change Java service/config/port behavior or establish physical-device teardown proof; [#66](https://github.com/novakin/vpn0wn-android/issues/66) delivered the shared UAPI/build repair in PR #67. [#68](https://github.com/novakin/vpn0wn-android/issues/68) subsequently delivered the enclosing Java/native query-admission repair through merged PR #69 at `6bb17579`; native warm-up retains its bind/JNI owners.

Current userspace source passes `GoBackend`'s exact `VpnService` and originating activation thread to JNI. The Android-owned native bind opens a fresh `StdNetBind` generation, protects every available IPv4/IPv6 socket inside `Open` at creation/rebind, then publishes it for sends. The version/match-checked overlay guards unavailable-family descriptors with `-1, syscall.EINVAL`; at least one real descriptor must be protected. Protection failure closes the unpublished sockets and fails activation/rebind. Cookie/control sends share this readiness boundary. The native context attaches/detaches callback workers; startup callbacks also check the originating thread's interrupt flag. After startup, callbacks check service lifetime only; an interrupted later Java caller must not permanently poison the shared activation context. Java operation boundaries own that caller's cancellation. Expected liveness/interruption exceptions and unexpected Java throwables retain their identity when JNI rethrows them on startup, the next native query, rebind or shutdown.

Warm-up eligibility comes from explicit UAPI ListenPort intent: nonzero enables it; absent/zero disables it, including later automatic reopens. One one-byte zero datagram attempt precedes each outgoing type-1 initiation on the same captured generation and Endpoint. Responses, cookies, keepalives and data get no extra packet. Expected warm-up I/O failure still permits the ordinary initiation; cancellation, descriptor closure and unexpected errors propagate. Recheck service/generation after potentially blocking warm-up before sending the initiation. WireGuard owns retry/rekey timing; add no sleep, acknowledgment, retry worker, timer or wake lock. The narrow pinned-source build overlay preserves the requested port on failed bind setup and closes bind/route-listener ownership on mark failure; cached upstream source is not patched and persisted profiles are unchanged; a cold build may download the validated module.

Shutdown marks the bind terminal and closes sockets to release blocked sends, stops/drains UAPI clients, closes the device and only then releases JNI references. The handle table admits reads without waiting under its lock and removes a closing handle before cancellation. Teardown cancels bind/UAPI I/O before draining admitted queries, then closes the device and releases JNI references. IDs increase without reuse within the native process, so a delayed lookup cannot acquire a replacement context; exhausting nonnegative 32-bit IDs fails startup. Java snapshots the tunnel/handle under its state lock, queries outside that lock and discards a result after identity changes. Java clears owned tunnel state before native teardown and publishes DOWN/restores service acquisition in cleanup even if JNI rethrows a callback defect. Existing transition ownership, service identity, config serialization and kernel behavior remain intact. Native warm-up replaces the separate Java five-attempt/200 ms preflight loop and late ignored socket-protection calls. Retained baseline APK/source and historical lifecycle/TrafficStats evidence keep their original scope; [source evidence and remaining physical limits](reviews/2026-10-07-protocol-preflight-experiment.md) own verification. The maintainer authorized adoption through PR #63 on 2026-10-08 (Europe/Paris). PR #63 records exact-head review/checks and actual delivery state. #61 remains open for physical, unchanged-server and DPI acceptance.

The historical [#37 compatibility decision](reviews/2026-10-07-udp-compatibility-review.md) rejects recovery of the preserved mandatory/random-port variant: it would reject endpoint-free profiles, replace configured ListenPort and remove merged lifecycle guards. Its extra packets, sleeps and new error/locales are not accepted behavior. That decision does not prove warm-up benefit or native port/NAT handoff; a future policy change needs a concrete reviewed requirement and authorization.

## Native handshake observations — #73 draft

The first [#73](https://github.com/novakin/vpn0wn-android/issues/73) source slice is merged through [PR #101](https://github.com/novakin/vpn0wn-android/pull/101) for userspace observations only. The version/match-checked overlay extends actual pinned protocol owners; it does not replace WireGuard retry/rekey timing. No recovery mutation, underlying-network callback, endpoint/DNS rewrite, UI, ping, wake lock or additional polling is included. Kernel observations and recovery are unavailable.

| Observation | Protocol-owned meaning |
| --- | --- |
| `ATTEMPT` | An outgoing initiation is attempted; the event distinguishes ordinary initiation from protocol retry. It does not establish a send. |
| `SENT` | The ordinary initiation's local socket send returned successfully; this is not remote delivery or acknowledgment. |
| `SEND_FAILED` | The ordinary initiation send failed with a fixed safe category. Protocol retry scheduling still belongs to WireGuard. |
| `AUTHENTICATED` | The protocol accepted a handshake response/session derivation or authenticated confirmation of the responder's new key. This establishes that peer's authentication event, not every peer or Internet reachability. |
| `EXHAUSTED` | The existing `handshakeAttempts > MaxTimerHandshakes` branch exhausted retries. Earlier retransmission expiry is progress/retry, not exhaustion. |

Each immutable `HandshakeObservation` carries a `HandshakeSession`, peer public key, event, retry flag where applicable, numeric runtime endpoint/address family when observed, sequence and monotonic `elapsedRealtimeMillis`. Unknown endpoint/family stays unknown; saved hostnames are not diagnostic numeric addresses. `SEND_FAILED` is the fixed safe failure category, with no raw error text. No private keys, PSKs, full config, raw native error/output or invented recovery count is retained. Idle silence and Doze produce no failure event.

Native `Device.Close` has a monotonic terminal state. The shared observation seam drops events once it observes that state, including `Peer.SendBuffers`' closed-device nil no-op without a socket send. This preserves upstream send return values and timer behavior. A native TUN-read failure can close the device before Java retires its activation; retained observations remain historical facts, not current health.

`GoBackend` allocates process-wide unique `HandshakeSession` IDs independently of its native handle IDs and statistics generations. A session exposes its read-only active lifetime. Native callbacks only stage at most the latest observation of each of five event kinds per configured peer. Handler delivery coalesces staged events and invokes `Tunnel`'s default `onHandshakeSessionChange` and `onHandshakeObservation` callbacks on Main outside all backend/native/context locks, preserving existing implementers. ## Retained-TUN userspace rebind — #73

`GoBackend.rebind(Tunnel)` is a synchronous userspace-library operation on the already-active captured tunnel. It preserves the Android TUN, native device, configuration, peers, handshake session and requested/current ListenPort while replacing native UDP sockets through the existing protected `Bind.Open`. No app caller or automatic trigger is added. It performs no DNS resolution, endpoint rewrite, UP restoration or saved-profile write. Kernel recovery is unsupported. Callers must run it off Main through their existing operation owner; the return value is not reachability evidence.

| Result | Meaning and effects |
| --- | --- |
| `true` | Native rebind settled successfully and the captured Java activation still matches. New sockets passed protection before publication. This does not prove a handshake or traffic delivery. |
| `false` | Tunnel is inactive, native device is closed, activation became obsolete, or UAPI/another rebind owns the IPC lock. Busy admission leaves sockets untouched; terminal/obsolete results never bring a replacement activation up. |
| `IOException` | Native rebind failed. Open/protection/mark failure leaves the retained TUN/device without a ready transport after closing failed new sockets. No hidden retry or rollback occurs; configured UP is not transport health. |
| `InterruptedException` | Caller interruption is observed before admission or after admitted native work settles. Preserve the interrupt flag. Post-operation cancellation may follow a completed socket replacement; it does not undo that operation or invalidate the retained JNI context. |

Service-lifetime failures and unexpected JNI callback throwables retain the existing exception identity. A genuine callback defect remains terminal for that native context; it is not converted into an ordinary recoverable socket failure.

Java captures tunnel, handle, service and activation under `stateLock`, releases the lock for JNI and checks identity after settlement. The native handle borrow prevents Device/JNI release during rebind; IDs are never reused. `Device.Rebind` uses `ipcMutex.TryLock` before mutation, so partial UAPI requests and concurrent rebinds return busy without interruption or waiting. After UP admission it closes captured bind I/O before `BindUpdate` waits for the network write lock, releasing sends that hold the corresponding read lock. The IPC lock remains held through socket replacement. It rechecks native UP afterward; Java rejects DOWN, destruction and same-tunnel replacement completions.

Terminal shutdown still removes handle admission, marks the bind stopped, closes sockets and UAPI clients, drains borrowed operations, then closes the device and frees JNI references. No rebind can publish sockets after terminal shutdown or reacquire a replacement handle. Explicit nonzero ListenPort keeps its existing warm-up eligibility; absent/zero remains disabled even when reopening an automatically selected port. Protocol retry/rekey timers remain WireGuard-owned. Offline controls and Android ABI compilation retain their source scope. [Rooted Android acceptance](reviews/2026-10-10-native-rebind-acceptance.md) separately verifies protected UDP replacement with retained TUN/session, synthetic authenticated HTTP traffic, debugger-injected protection failure/retry and actual Android service destruction followed by fresh activation, with original state restored. Actual OS protection denial, concurrent phone races, interruption, network handover, packet protection, IPv6 traffic, DPI, speed and battery acceptance remain open under #73/#61.

The later [physical port-lifecycle record](reviews/2026-10-12-udp-port-release-acceptance.md) verifies independent IPv4/IPv6 collision/reuse after rebind, DOWN and genuine service destruction, plus same-process fresh activation. | `RecoveryResult.outcome` | Mutation and initiation evidence |
| --- | --- |
| `BUSY`, `OBSOLETE`, `UNAVAILABLE` | Proven no socket mutation by this request; unavailable does not promise a usable context. |

### Eligible triggers and finite limits

Only a fresh, attributed native `EXHAUSTED` cycle for a configured peer in the captured active userspace `HandshakeSession`, with a known current numeric runtime endpoint, may qualify. Native admission must claim that exact still-exhausted cycle. Java event sequence is capture order, not a native cycle identity or failure count. Peers without a current numeric runtime endpoint, unknown attribution and kernel mode cannot trigger recovery. A peer with no saved Endpoint can qualify after learning a numeric endpoint natively; recovery does not write that endpoint into its profile. A qualifying peer's socket replacement affects every peer sharing the activation's transport.

`ATTEMPT`, retries, `SENT` and a single `SEND_FAILED` remain observations while WireGuard owns its retry timing. Authentication superseding the triggering cycle before admission suppresses it; authentication after admission requires conservative reconciliation. Idle silence, old handshake/statistics, screen off, wake, Doze exit and network changes alone never trigger replacement. Known deep Doze suppresses new admission without consuming a charge or creating a wake queue; unknown power/reachability remains unknown.

Selected engineering defaults, not measured optimums:

- At most **two conservatively charged transport attempts per native activation**, **one pending/in-flight request**, and **30 seconds between charged attempts**. The manager claims the request slot on Main before waiting for `operationLock`; competing peer triggers update bounded per-configured-peer episode evidence and drop without creating another waiter. A fresh early trigger is recorded as rate-limited and dropped without a queue or retry timer. The shared budget already bounds every peer.
- Reserve a charge before backend entry. Commit charged spacing from the actual backend-body entry time only after admitted or unknown settlement; delayed IO dispatch cannot shorten that spacing. Refund only an explicitly proven non-mutating refusal or a body that never entered; that refusal does not advance charged-attempt spacing. Track confirmed admissions, charged usage and unknown settlement separately.
- At most **four backend admission requests per activation**. A positively identified non-mutating busy result permits **one cancellable 1-second deferral for that trigger**. A second busy refusal gets no further deferral; obsolete, unavailable, cancelled, ambiguous and terminal-context outcomes get no retry.
- Ambiguous settlement or a terminal/unusable JNI context disables all further automatic requests for that activation, including fresh triggers. Ordinary admitted I/O failure remains charged; only a positively reusable context and a new qualifying native cycle may use remaining budget. An `IOException` or native `-EIO` alone proves neither reusability nor permission to retry.
- Only a fresh native activation refills the budget. Later authentication permits a genuinely new failure within remaining budget; no-op UP, view recreation, selection, wake, old events and network churn do not refill it.

Do not wait on a running retransmit callback whose blocked send can hold the network read lock; retain deterministic native race controls for this claim/lock design.

After valid claim, replace protected sockets through the retained bind owner. Transport readiness permits **at most one ordinary initiation request for the triggering peer**. Protection failure, cancellation, authentication progress or native throttle may start no cycle. `SendHandshakeInitiation(false)` can return nil after throttling, empty staged queues send nothing, and keepalive can use existing keys. Distinguish initiation started, skipped/progressed and failed evidence; neither nil nor successful rebind proves initiation or authenticated recovery. Interruption and terminal defects retain their exception identity; unusable-context evidence remains visible even when no throwable accompanies native failure.

Keep manual/store transition serialization. Existing boot/system restoration stays unchanged; #74's manual-versus-always-on/automation arbitration remains a separate choice.

`ObservableTunnel.onHandshakeObservation` hands only accepted current EXHAUSTED evidence to `TunnelManager.onHandshakeExhausted`; neither statistics nor cached exhaustion is scanned for triggers. ### Experimental password archive codec — #196

`VpsBackupArchive.encrypt/decrypt` encode the validated snapshot as bounded authenticated bytes, independently of the original installation or Keystore. This remains an experimental source candidate; the separate [private export integration](#private-encrypted-server-export-candidate--196) adds its first writer caller without freezing the format. The [scoped native record](reviews/2026-10-16-native-backup-codec-acceptance.md) establishes producer-artifact API24/API36 linkage, interoperability and named heap/cancellation controls. The initial API36 cold cohort fails the proposed 2,000 ms p95 target at 3044.284840 ms; a separate settled diagnostic passes only its conditioned scope. A separate fresh-boot diagnostic has p95 1660.850712 ms and retains its 6004.295886 ms maximum; it does not replace the initial failure. Overall cold-performance acceptance and writer-format freeze remain open, alongside physical/OEM, production UI and integration gates. No restore or distribution acceptance follows; #196 remains open.

The single candidate profile is Argon2id v1.3 with 19,456 KiB, two passes, one lane, a fresh 16-byte salt and a 32-byte derived AES key. Bouncy Castle's pinned lightweight byte API supplies the KDF on every supported API level; it registers no provider. Platform `AES/GCM/NoPadding` uses that key with a fresh 12-byte nonce and 128-bit tag, without selecting a provider. [The dependency decision](architecture.md#experimental-portable-backup-cryptography--196-2026-10-16) and [notice/provenance record](license-attribution.md#bouncy-castle-backup-kdf-notice) own the compatibility tradeoff. Current [OWASP password guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#password-hashing-algorithms), checked 2026-10-16, prefers the selected Argon2id minimum and marks PBKDF2-SHA1 legacy-only; the older 1.3-million-iteration proposal is not implemented. Android documents PBKDF2-SHA256 only from API 26; no minimum SDK bump or hand-written KDF bridges that gap.

The fixed 56-byte header consists of ASCII `VPN0WNBK` (offset 0, eight bytes); archive version, cipher suite, KDF and Argon2 version (offsets 8–11, one byte each, exactly `1`, `1`, `1`, `0x13`); memory KiB, passes and lanes (offsets 12, 16 and 20, unsigned big-endian 32-bit values exactly `19456`, `2`, `1`); salt (offset 24, 16 bytes); nonce (offset 40, 12 bytes); and ciphertext-plus-tag length (offset 52, unsigned big-endian 32-bit). Ciphertext immediately follows; its last 16 bytes are the GCM tag. All original header bytes are AAD. Unknown identifiers, non-exact costs, overflowed/mismatched lengths, truncation and trailing bytes are rejected before KDF allocation. Plaintext is at most 786,432 bytes; ciphertext including tag is 17–786,448 bytes; the complete archive is at most 786,504 bytes. Future file readers must enforce that cap during acquisition, even when provider size metadata lies; this byte-array codec does not acquire URI streams.

Plaintext explicitly serializes `ok`, `snapshotVersion`, `capturedAtUtc`, `interface`, `config`, `revokedCount` and `revoked`, preserving snapshot text and its existing parser/field/count/total bounds. `ProvisioningJson.encodeBackup` now owns this bounded serialization for the codec and restore client; the envelope, JSON schema, Argon2id costs and password rules are unchanged. JSON field order is not a canonicalization requirement. Invalid UTF-16/UTF-8 and serialization expansion beyond the cap fail without truncation. One bounded `doFinal` authenticates before plaintext reaches strict UTF-8 decoding or the existing snapshot validator. Wrong passwords and failed tags share one fixed safe error; diagnostics contain neither secret data nor provider/JSON payloads. Authentication does not validate privileged restore grammar.

Password bytes are exact UTF-8 scalar values: no normalization, trimming, case conversion, replacement, pre-hashing or NUL terminator. Composed and decomposed text remain different; embedded U+0000 is supported. Creation accepts 15–128 scalar values; decryption accepts 1–128 to avoid coupling recovery to later creation-policy changes. Both reject unpaired surrogates, more than 256 UTF-16 code units or more than 512 UTF-8 bytes, never truncating. Eventual prompts must confirm the password, describe the limit and unrecoverable loss, and support paste/password managers; the private export candidate implements that prompt without changing these rules.

The codec copies caller password characters and leaves the caller's array intact; callers must clear their own copy. Structured Default work keeps CPU crypto off Main. Cancellation checks surround the non-cooperative KDF and precede result publication; the worker settles before the owned character/UTF-8/key/plaintext arrays are cleared. No secret enters StateFlow, saved state, fleet settings, logs or a plaintext file. Snapshot strings, library/provider copies and exceptional VM termination prevent a complete memory-erasure guarantee. [QA](qa-test-plan.md#experimental-password-archive-controls--196) owns executed proof and remaining gates.
