The existing [Config](../tunnel/src/main/java/com/vpn0wn/config/Config.java), Interface, Peer and endpoint/address types own parse/serialize behavior. Preserve repeated list fields, multi-peer profiles, IPv6 endpoint syntax and other supported WireGuard fields. Generated provisioning profiles must pass these same parsers/import paths.

| Section | Accepted attributes |
| --- | --- |
| Interface | `Address`, `DNS`, `ExcludedApplications`, `IncludedApplications`, `ListenPort`, `MTU`, `PrivateKey`. |
| Peer | `AllowedIPs`, `Endpoint`, `PersistentKeepalive`, `PresharedKey`, `PublicKey`. |

Private/public key requirements and value validation belong to those parsers. Peer Endpoint is optional; IPv6 endpoint literals use `[address]:port`. Unknown attributes, including wg-quick hooks and `SaveConfig`, are rejected. DNS serializes when servers or search domains exist, preserving domain-only and mixed IPv4/IPv6/search-domain profiles across save/export round trips. Existing ordering groups servers before search domains; repeated entries retain the parser's set semantics. Explicit prefixes must be 0–32 for IPv4 or 0–128 for IPv6; negative or oversized values throw ParseException, wrapped with the existing Interface Address/Peer AllowedIPs location by config parsing. Omitted prefixes remain host masks (32/128). #16 merged these repairs in PR #26; no file migration or automatic rewrite is performed.

Backend state uses `DOWN`, `UP` and `TOGGLE`. `TunnelManager` uses TOGGLE as an in-progress observable transition; it is not proof of an active VPN. Its coroutine mutex serializes mutations and state snapshots. Waiting admission remains cancellable; admitted operations finish backend/store/model reconciliation before propagating caller cancellation. Explicit DOWN queues behind earlier UP/TOGGLE, including requests not yet admitted. Deleted model references cannot reactivate a tunnel. Delete disconnects the observed backend before removing persistence/model ownership; failed deletion attempts restoration. Failed config saves retain the cached/persisted profile and attempt runtime restoration; recovery errors remain attached to the failure.

Kernel interfaces can remain UP after app/process recreation even though the new `WgQuickBackend` has no cached running configuration. The manager supplies the managed profile for an observed-UP kernel DOWN, including toggle, active delete, rename and backend switching, so the existing wg-quick cleanup can run. Configuration remains model/store-owned; no raw interface removal substitutes for cleanup. Userspace DOWN remains independent of configuration loading, and already-DOWN kernel profiles require no configuration read merely for no-op shutdown or deletion. [#109](https://github.com/novakin/vpn0wn-android/issues/109) owns the discovered contract mismatch; [PR #110](https://github.com/novakin/vpn0wn-android/pull/110) owns delivery and scoped recreated-backend/rooted-device acceptance.

Initialization settles inventory waiters on failure/cancellation and retries failed loads. Inventory becomes available before automatic restoration; restoration children stay attached to their caller. Application backend initialization also settles cancellation instead of publishing fallback success. Backend notifications reconcile current observed state under the same manager lock; they preserve persisted restoration intent after spontaneous service loss. Explicit manager requests own changes to that intent. Detail config/statistics completions require the same binding and selected tunnel; destroyed views cancel their jobs. These scoped repairs merged in PR #25; complete kernel transition serialization merged in PR #27 under #15 as described below.

Backend switching drains prior transitions and disconnects tunnels under the manager admission lock before changing the preference. After that commit, queued mutations are rejected until restart; failed/cancelled restart restores the previous preference and releases the reservation. Shutdown failure can leave already-stopped tunnels down with their profiles intact, but restores usable controls. Preference rollback failure remains visible and keeps the reservation; it is not successful switching.

`GoBackend` manages Android VpnService and userspace/native activation; `WgQuickBackend` manages root/kernel commands. Preserve required permission/service setup and explicit ordering. A stale/destroyed service must not be reused; teardown cannot block the main thread waiting for long activation.

The native tunnel handle owns a standard Unix listener and accepted clients through `uapiserver.Server`. `Listen` preserves `/data/data/<application-id>/cache/wireguard/<interface>.sock`, creates new directories privately and applies socket mode 0600 before serving. It refuses an active socket, bounds the local probe to one second and replaces a stale socket only after connection refusal and confirmation that the path is a socket. Access denial, unexpected probe errors and non-socket paths are not treated as stale success. Teardown closes/unlinks the listener, waits for admission to stop, closes remaining clients and waits for their `IpcHandle` handlers before closing the device. Startup failures follow the same ordering. Closing a client unblocks an idle or partial request holding the pinned IPC lock; it does not roll back admitted settings. The Android owner replaces upstream queued acceptance, file duplication and deletion-watcher goroutines; unlinking the socket externally does not terminate the native device. Failed initial settings close the complete owned device. These source controls do not change Java service/config/port behavior or establish physical-device teardown proof; [#66](https://github.com/novakin/vpn0wn-android/issues/66) delivered the shared UAPI/build repair in PR #67. [#68](https://github.com/novakin/vpn0wn-android/issues/68) subsequently delivered the enclosing Java/native query-admission repair through merged PR #69 at `6bb17579`; native warm-up retains its bind/JNI owners.

Current userspace source passes `GoBackend`'s exact `VpnService` and originating activation thread to JNI. The Android-owned native bind opens a fresh `StdNetBind` generation, protects every available IPv4/IPv6 socket inside `Open` at creation/rebind, then publishes it for sends. The version/match-checked overlay guards unavailable-family descriptors with `-1, syscall.EINVAL`; at least one real descriptor must be protected. Protection failure closes the unpublished sockets and fails activation/rebind. Cookie/control sends share this readiness boundary. The native context attaches/detaches callback workers; startup callbacks also check the originating thread's interrupt flag. After startup, callbacks check service lifetime only; an interrupted later Java caller must not permanently poison the shared activation context. Java operation boundaries own that caller's cancellation. Expected liveness/interruption exceptions and unexpected Java throwables retain their identity when JNI rethrows them on startup, the next native query, rebind or shutdown.

Warm-up eligibility comes from explicit UAPI ListenPort intent: nonzero enables it; absent/zero disables it, including later automatic reopens. One one-byte zero datagram attempt precedes each outgoing type-1 initiation on the same captured generation and Endpoint. Responses, cookies, keepalives and data get no extra packet. Expected warm-up I/O failure still permits the ordinary initiation; cancellation, descriptor closure and unexpected errors propagate. Recheck service/generation after potentially blocking warm-up before sending the initiation. WireGuard owns retry/rekey timing; add no sleep, acknowledgment, retry worker, timer or wake lock. The narrow pinned-source build overlay preserves the requested port on failed bind setup and closes bind/route-listener ownership on mark failure; cached upstream source is not patched and persisted profiles are unchanged; a cold build may download the validated module.

Shutdown marks the bind terminal and closes sockets to release blocked sends, stops/drains UAPI clients, closes the device and only then releases JNI references. The handle table admits reads without waiting under its lock and removes a closing handle before cancellation. Teardown cancels bind/UAPI I/O before draining admitted queries, then closes the device and releases JNI references. IDs increase without reuse within the native process, so a delayed lookup cannot acquire a replacement context; exhausting nonnegative 32-bit IDs fails startup. Java snapshots the tunnel/handle under its state lock, queries outside that lock and discards a result after identity changes. Java clears owned tunnel state before native teardown and publishes DOWN/restores service acquisition in cleanup even if JNI rethrows a callback defect. Existing transition ownership, service identity, config serialization and kernel behavior remain intact. Native warm-up replaces the separate Java five-attempt/200 ms preflight loop and late ignored socket-protection calls. Retained baseline APK/source and historical lifecycle/TrafficStats evidence keep their original scope; [source evidence and remaining physical limits](reviews/2026-10-07-protocol-preflight-experiment.md) own verification. The maintainer authorized adoption through PR #63 on 2026-10-08 (Europe/Paris). PR #63 records exact-head review/checks and actual delivery state. #61 remains open for physical, unchanged-server and DPI acceptance.

The historical [#37 compatibility decision](reviews/2026-10-07-udp-compatibility-review.md) rejects recovery of the preserved mandatory/random-port variant: it would reject endpoint-free profiles, replace configured ListenPort and remove merged lifecycle guards. Its extra packets, sleeps and new error/locales are not accepted behavior. That decision does not prove warm-up benefit or native port/NAT handoff; a future policy change needs a concrete reviewed requirement and authorization.

Socket continuity and authenticated loopback traffic do not establish hardware deep suspend, broader unchanged kernel-server compatibility or DPI benefit. ## Native handshake observations — #73 draft

The first [#73](https://github.com/novakin/vpn0wn-android/issues/73) source slice is merged through [PR #101](https://github.com/novakin/vpn0wn-android/pull/101) for userspace observations only. The version/match-checked overlay extends actual pinned protocol owners; it does not replace WireGuard retry/rekey timing. No recovery mutation, underlying-network callback, endpoint/DNS rewrite, UI, ping, wake lock or additional polling is included. Kernel observations and recovery are unavailable.

| Observation | Protocol-owned meaning |
| --- | --- |
| `ATTEMPT` | An outgoing initiation is attempted; the event distinguishes ordinary initiation from protocol retry. It does not establish a send. |
| `SENT` | The ordinary initiation's local socket send returned successfully; this is not remote delivery or acknowledgment. |
| `SEND_FAILED` | The ordinary initiation send failed with a fixed safe category. Protocol retry scheduling still belongs to WireGuard. |
| `AUTHENTICATED` | The protocol accepted a handshake response/session derivation or authenticated confirmation of the responder's new key. This establishes that peer's authentication event, not every peer or Internet reachability. |
| `EXHAUSTED` | The existing `handshakeAttempts > MaxTimerHandshakes` branch exhausted retries. Earlier retransmission expiry is progress/retry, not exhaustion. |

Each immutable `HandshakeObservation` carries a `HandshakeSession`, peer public key, event, retry flag where applicable, numeric runtime endpoint/address family when observed, sequence and monotonic `elapsedRealtimeMillis`. Unknown endpoint/family stays unknown; saved hostnames are not diagnostic numeric addresses. `SEND_FAILED` is the fixed safe failure category, with no raw error text. No private keys, PSKs, full config, raw native error/output or invented recovery count is retained. Idle silence and Doze produce no failure event.

Native `Device.Close` has a monotonic terminal state. The shared observation seam drops events once it observes that state, including `Peer.SendBuffers`' closed-device nil no-op without a socket send. This preserves upstream send return values and timer behavior. A native TUN-read failure can close the device before Java retires its activation; retained observations remain historical facts, not current health.

`GoBackend` allocates process-wide unique `HandshakeSession` IDs independently of its native handle IDs and statistics generations. A session exposes its read-only active lifetime. Native callbacks only stage at most the latest observation of each of five event kinds per configured peer. Handler delivery coalesces staged events and invokes `Tunnel`'s default `onHandshakeSessionChange` and `onHandshakeObservation` callbacks on Main outside all backend/native/context locks, preserving existing implementers. Implementations must return promptly and schedule blocking work through its owner. Unknown/unconfigured peer events do not grow storage or become an attributed peer result. Sequence orders Java capture/delivery across coalescing; concurrent peer work or receipt/local-send completion has no additional causal ordering promise. Discarded intermediate events create gaps, so observations provide no attempt/send/recovery count. Early startup observations wait for successful native activation. Failed startup and obsolete activations discard them. Session lifecycle publication establishes the model's atomic activation identity; identity must match before and after Main dispatch. DOWN, native replacement and service teardown invalidate active diagnostics before delayed work can publish.

`ObservableTunnel.handshakeDiagnostics` exposes nullable read-only `Map<Key, PeerHandshakeDiagnostics>` snapshots: null means unavailable, DOWN or kernel; an empty map means active userspace with no observed event. Each observed peer retains `lastObservation`, `lastAttempt`, `lastSendResult`, `lastAuthenticated` and `lastExhausted` within that activation. Missing event kinds remain null. A later event does not erase those distinct facts or make an old failure current health. No observation infers reachability, active transport recovery or counters; no history survives as active diagnostics after DOWN/replacement. This activation identity is separate from statistics cache invalidation. The first source slice added no Fragment/DataBinding presentation.

The Detail peer-card presenter now shows `LAST HANDSHAKE EVENT`, `OBSERVED ENDPOINT` and `ADDRESS FAMILY` from each configured peer's `lastObservation`. `BindingAdapters.setDetailPeers` reuses `setItems` inflation and assigns diagnostics by peer public key, independently of row/map order. A null diagnostic map or DOWN/null state shows observations unavailable; an available empty map or missing configured peer shows no handshake event observed. Default/French resources distinguish all five events and the ATTEMPT retry flag. Local-send, authentication and exhaustion text describes recorded events, not current health or Internet reachability. Endpoint and IPv4/IPv6 family come only from that observation; unknown values show `—`, with no saved-hostname fallback. The presenter exposes only the latest observation; distinct retained attempt/send/authentication/exhaustion facts are unchanged. `TunnelDetailFragment.onDestroyView` unbinds generated model listeners. This slice adds no relative event ages, recovery counts/actions, DNS, backend mutation or polling. [Scoped rooted Android presenter acceptance](reviews/2026-10-10-peer-diagnostics-acceptance.md) adds physical peer-event, invalidation, reconnect and output evidence with restored state and exact source/APK provenance. ## Retained-TUN userspace rebind — #73

`GoBackend.rebind(Tunnel)` is a synchronous userspace-library operation on the already-active captured tunnel. It preserves the Android TUN, native device, configuration, peers, handshake session and requested/current ListenPort while replacing native UDP sockets through the existing protected `Bind.Open`. No app caller or automatic trigger is added. It performs no DNS resolution, endpoint rewrite, UP restoration or saved-profile write. Kernel recovery is unsupported. Callers must run it off Main through their existing operation owner; the return value is not reachability evidence.

| Result | Meaning and effects |
| --- | --- |
| `true` | Native rebind settled successfully and the captured Java activation still matches. New sockets passed protection before publication. This does not prove a handshake or traffic delivery. |
| `false` | Tunnel is inactive, native device is closed, activation became obsolete, or UAPI/another rebind owns the IPC lock. Busy admission leaves sockets untouched; terminal/obsolete results never bring a replacement activation up. |
| `IOException` | Native rebind failed. Open/protection/mark failure leaves the retained TUN/device without a ready transport after closing failed new sockets. No hidden retry or rollback occurs; configured UP is not transport health. |
| `InterruptedException` | Caller interruption is observed before admission or after admitted native work settles. Preserve the interrupt flag. Post-operation cancellation may follow a completed socket replacement; it does not undo that operation or invalidate the retained JNI context. |

Service-lifetime failures and unexpected JNI callback throwables retain the existing exception identity. A genuine callback defect remains terminal for that native context; it is not converted into an ordinary recoverable socket failure.

Java captures tunnel, handle, service and activation under `stateLock`, releases the lock for JNI and checks identity after settlement. The native handle borrow prevents Device/JNI release during rebind; IDs are never reused. `Device.Rebind` uses `ipcMutex.TryLock` before mutation, so partial UAPI requests and concurrent rebinds return busy without interruption or waiting. After UP admission it closes captured bind I/O before `BindUpdate` waits for the network write lock, releasing sends that hold the corresponding read lock. The IPC lock remains held through socket replacement. It rechecks native UP afterward; Java rejects DOWN, destruction and same-tunnel replacement completions.

Terminal shutdown still removes handle admission, marks the bind stopped, closes sockets and UAPI clients, drains borrowed operations, then closes the device and frees JNI references. No rebind can publish sockets after terminal shutdown or reacquire a replacement handle. Explicit nonzero ListenPort keeps its existing warm-up eligibility; absent/zero remains disabled even when reopening an automatically selected port. Protocol retry/rekey timers remain WireGuard-owned. Offline controls and Android ABI compilation retain their source scope. [Rooted Android acceptance](reviews/2026-10-10-native-rebind-acceptance.md) separately verifies protected UDP replacement with retained TUN/session, synthetic authenticated HTTP traffic, debugger-injected protection failure/retry and actual Android service destruction followed by fresh activation, with original state restored. Actual OS protection denial, concurrent phone races, interruption, network handover, packet protection, IPv6 traffic, DPI, speed and battery acceptance remain open under #73/#61.

## Proposed bounded automatic recovery — #73

**Status — 2026-10-10 (Europe/Paris):** recommended, independently ultra-reviewed planning contract for [#73](https://github.com/novakin/vpn0wn-android/issues/73). Documentation adoption records the proposal; it does not select new runtime/API policy or defaults, implement a controller or add runtime proof. Existing observations and `GoBackend.rebind(Tunnel)` remain unchanged. The maintainer must select this exhaustion-only numeric-endpoint pilot before automatic implementation; broader hostname/handover acceptance keeps #73 open.

### Eligible triggers and finite limits

Only a fresh, attributed native `EXHAUSTED` cycle for a configured peer in the captured active userspace `HandshakeSession`, with a known current numeric runtime endpoint, may qualify. Native admission must claim that exact still-exhausted cycle. Java event sequence is capture order, not a native cycle identity or failure count. Endpoint-free peers, unknown attribution/endpoints and kernel mode cannot trigger recovery; a qualifying peer's socket replacement affects every peer sharing the activation's transport.

`ATTEMPT`, retries, `SENT` and a single `SEND_FAILED` remain observations while WireGuard owns its retry timing. Authentication superseding the triggering cycle before admission suppresses it; authentication after admission requires conservative reconciliation. Idle silence, old handshake/statistics, screen off, wake, Doze exit and network changes alone never trigger replacement. Known deep Doze suppresses new admission without consuming a slot or creating a wake queue; unknown power/reachability remains unknown.

Proposed engineering defaults, not measured optimums:

- At most **two conservatively charged transport attempts per native activation**, **one recovery in flight**, and **30 seconds between charged attempts**. Coalesce competing peer triggers into bounded current evidence without parallel rebinds or an unbounded queue. A fresh early trigger is recorded as rate-limited and dropped without a queue or retry timer. The shared budget already bounds every peer.
- Reserve a slot before backend entry. Refund only an explicitly proven non-mutating refusal; that refusal does not advance charged-attempt spacing. Confirmed admission and unresolved exception/cancellation retain the charge. Track confirmed admissions, charged usage and unknown settlement separately.
- At most **four backend admission requests per activation**. A positively identified non-mutating busy result permits **one cancellable 1-second deferral for that trigger**. A second busy refusal gets no further deferral; obsolete, unavailable, cancelled, ambiguous and terminal-context outcomes get no retry.
- Ambiguous settlement or a terminal/unusable JNI context disables all further automatic requests for that activation, including fresh triggers. Ordinary admitted I/O failure remains charged; only a positively reusable context and a new qualifying native cycle may use remaining budget. An `IOException` or native `-EIO` alone proves neither reusability nor permission to retry.
- Only a fresh native activation refills the budget. Later authentication permits a genuinely new failure within remaining budget; no-op UP, view recreation, selection, wake, old events and network churn do not refill it.

### Admission, native claim and settlement

Extend existing manager/model/backend/native owners, with no setting, monitoring service, extra statistics polling, ping, wake lock or general scheduler. Manager admission captures the exact managed model, backend instance, active session, triggering peer, event sequence and monotonic time. A narrow expected-session backend entry point must compare that session **inside backend admission** before native lookup, while preserving the existing library rebind method. Capture exact service, activation and nonreused native handle under `stateLock`; the bind retains socket-generation ownership. Recheck captured identities after settlement; a stale trigger must never acquire a replacement activation of the same model.

The current EXHAUSTED hook publishes before native keepalive deletion, staged-packet flush and zero-key cleanup setup. Move publication after these effects or provide equivalent settled native admission. The timer/protocol owner must atomically claim the triggering exhausted episode, rejecting delayed exhaustion A after a later cycle B and authenticated progress. An IPC-mutex check alone cannot serialize timer/send/authenticated-receive paths. Do not wait on a running retransmit callback whose blocked send can hold the network read lock; exact claim/lock design needs deterministic race proof before implementation.

After valid claim, replace protected sockets through the retained bind owner. Transport readiness permits **at most one ordinary initiation request for the triggering peer**. Protection failure, cancellation, authentication progress or native throttle may start no cycle. `SendHandshakeInitiation(false)` can return nil after throttling, empty staged queues send nothing, and keepalive can use existing keys. Distinguish initiation started, skipped/progressed and failed evidence; neither nil nor successful rebind proves initiation or authenticated recovery. Preserve protocol bytes, native retry/rekey timing, TUN/device/session, peer destinations/settings/keys, requested/current ListenPort and explicit-versus-automatic warm-up intent.

The proposed automatic entry point needs owner outcomes distinguishing non-mutating busy, non-mutating obsolete/no-longer-needed, admitted transport ready and admitted transport failed. Existing boolean `false` can follow mutation with obsolete identity and cannot drive accounting or deferral. Interruption and terminal defects retain their exception identity; unusable-context evidence must remain visible even when no throwable accompanies native failure.

Keep manual/store transition serialization. Recovery uses short manager admission/reconciliation sections, with blocking JNI off Main and outside both `operationLock` and `stateLock`; do not hold `mutate`'s full-lifetime noncancellable lock across recovery. DOWN must reach native socket cancellation. Manual DOWN/toggle-to-DOWN, reconnect, config/name/delete and backend switching invalidate recovery at manager admission without changing earlier manual-transition ordering. UI/tile/authorized remote UP/DOWN are manual requests; refresh, boot and system always-on restoration are not. Recovery never calls UP, restores a deleted model or writes restoration intent. Existing boot/system restoration stays unchanged; #74's manual-versus-always-on/automation arbitration remains a separate choice.

Pre-admission cancellation removes pending work and propagates cancellation. After admission, cancel deferrals, settle owned native work, reconcile only the captured current session, then propagate cancellation. Do not infer rollback, refund an unresolved slot, report success to a cancelled caller or start another cycle from cancellation. DOWN/replacement/service destruction retire the session and reject obsolete completion. ### Full app-data transfer

`AppDataTransfer` owns a version-1 ZIP schema: exact root `migration.json`, `format="vpn0wn-transfer"`, integer `version=1`, typed `settings`, a `servers` array, an exact profile-name inventory, and `profiles/<valid tunnel name>.conf`. It uses the existing Config parser and serialization, never extracts arbitrary files, and rejects duplicate entries, missing/undeclared profiles, unsupported versions, unknown settings/paths and malformed consumed types. The manifest inventory prevents a complete-entry ZIP prefix from silently importing fewer profiles. Bounds are 256 profiles, 1 MiB expanded per entry and 16 MiB expanded per archive; they are enforced while reading, independent of ZIP-reported sizes. Settings/fleet-only archives are valid. Parser failures expose fixed messages without secret-bearing parser causes.

Portable settings are present values of `dark_theme`, `multiple_tunnels`, `restore_on_boot` and `allow_remote_control_intents`, plus a resolvable `last_used_tunnel`. Omitted fields preserve destination values. Kernel backend selection, active/restoration state, tile membership, updater/installation consent, permissions, Android VPN policy and credentials are not imported. Stored VPS metadata retains its existing 16 fields, including the nullable running observation and historical sync time; transfer does not refresh server health. The archive boundary requires all 16 typed fleet fields. Local-store transfer snapshots also accept the evidenced original 15-field writer shape, normalizing only absent `running` to unknown; all other missing/malformed/unknown fields still fail. The ordinary legacy reader retains its existing coercion/drop behavior. Invalid source or destination metadata blocks transfer rather than rewriting it as empty.

`TunnelManager.exportAppData` captures names/configs under existing mutation admission, settles earlier ordered last-used writes, then reads one settings/fleet snapshot. `importAppData` checks all destination profile conflicts and selection before writes. Identical canonical wg-quick profiles retain their current managed identity/state; different same-name profiles or same-ID server records reject the batch. Lock order is manager admission, then DataStore. When stale restoration markers overlap absent profiles being imported, an initial awaited edit validates fleet conflicts and durably removes only those names before any file creation. Failure of this preparation creates no profiles; its removal of invalid restoration intent remains committed if later import fails. This protects a file surviving failed rollback from boot restoration. One subsequent edit validates current fleet metadata, creates new profiles through ConfigStore and applies the combined settings/fleet values. Publication occurs only after that metadata commit. Imported profiles remain DOWN, and existing active profiles are not transitioned. Restoration also snapshots eligible managed identities before suspending for saved state, so concurrent imports cannot inherit startup activation intent.

Precommit failure rolls back only successfully created, operation-owned profiles. Failed rollback publishes surviving new profiles DOWN and reports incomplete recovery; cancellation and programming defects propagate after settlement. Cancellation before admission changes nothing; after admission the batch commits or recovers before caller cancellation is reported. These are app-process sequencing and recovery guarantees, not one process-death/power-loss transaction across profile files and DataStore. Retry skips identical committed data but rejects unresolved conflicts. Settings confirmation warns that imported preferences can enable remote control and restore on boot. Export retains administrator/biometric gates and uses a new non-overwriting Downloads name. [Operations](operations.md#app-data-transfer) owns private-file handling and migration order; [QA](qa-test-plan.md#full-app-data-transfer-acceptance) owns remaining artifact/device proof.

`BiometricAuthenticator` owns the shared system-authentication boundary for full/profile ZIP export and private-key reveal. A successful availability check opens Android's weak-biometric-or-device-credential prompt; only prompt success authorizes a configured authenticator. `NoAuthenticationConfigured` permits the existing no-lock behavior only when Android reports a present, nonsecure Keyguard and no enrollment or no biometric hardware. Transient, unsupported, unknown and secure-device preflight failures are terminal failures, and runtime authentication errors never authorize the request. Cancellation remains cancellation; a failed biometric sample remains nonterminal so the same prompt can succeed later. These decisions use supported Android platform reports rather than an app password or private authentication service.

## Result, error and cancellation meaning

`ProvisioningCommandOutput` carries exit code/stdout/stderr. A zero exit passes `requireSuccess`; nonzero throws a category/exit-code exception while retaining the internal output for the responsible caller. Internal output may contain secrets and is not a diagnostic string.

`RootShell.run()` preserves returned stdout, marker framing and exit status without logging commands or stream payloads. Root startup diagnostics also omit raw UID/error output. Provisioning command failures log only their exit code/category. `ProvisioningJson` guards the full response, including nested arrays and peer rows; shape/parser failures carry no output or parser cause. Cleanup warnings omit exception payloads and preserve the completed result. [C1 evidence](development.md#c1-secret-safe-logging--2026-10-06) retains its historical scope; [C4 evidence](development.md#c4-provisioning-contracts-and-observed-health--2026-10-06) covers strict schemas and remote errors. C9 now applies payload-free failures to the disposable harness; future transport diagnostics still need handling at their owner.

JSON requires an actual `ok` Boolean. Consumed success strings, Booleans, arrays and nested objects are required and strictly typed, except optional `cleanupPath` and remove-only `archive` strings. Revoked success requires a nonblank archive string. Plan requires `supported:true`; peer mutation requires `removed:true`; uninstall requires `uninstalled:true`. Unknown extra fields are ignored. Numeric counters are decimal strings bounded by signed Long; `revokedCount` is bounded by signed Int. Running and peer handshake/RX/TX fields require Boolean/decimal-string or explicit null as appropriate. Null means unavailable observation, zero means an observed zero; missing fields and invalid/negative/overflow values are invalid responses.

Legacy string-only mutation results are intentionally rejected. The app uploads its packaged bundle per operation; pair the parser and scripts from the same reviewed revision.

Structured failures require string `error` and `message` fields, but remote text never becomes diagnostics. `ProvisioningFailureCategory` supplies fixed messages; the allowlist in `ProvisioningJson.remoteFailure` supplies a safe `remoteCode` only for supported codes. Unknown codes map to REMOTE_FAILURE without retaining the code. Missing/malformed fields map to INVALID_RESPONSE. Script execution consumes `ok:false` even on a nonzero exit, preserving the safe category/recovery; nonzero `ok:true` is still command failure. Generic command failures retain internal output under the contract above.

C2–C3 mutation failures additionally expose `recovery`, `recoveryPath` and `artifact`. Android keeps only the recovery enum: UNCHANGED, RESTORED, INCOMPLETE or UNKNOWN for an unrecognized/malformed present value; absent recovery stays null. INCOMPLETE/UNKNOWN adds a fixed inspection warning. Untrusted recovery paths/artifact text are not retained in exceptions. Successful install/add/remove/revoke/uninstall models expose optional `cleanupPath` (empty when absent or clean). Live UI presentation of recovery/cleanup remains C12; operator handling follows [operations](operations.md#provisioning-mutation-recovery).

The existing guarded shell boundary has a 30-second default execute/upload coroutine timeout, preserves cancellation and maps expected IO failures. Factory checks require a fingerprint when trust is disabled and at least one auth attempt. These are wrapper checks, not proof of host-key verification or real channel/session closure. C11 must implement and test those behaviors against the chosen SSH library.

Command success is limited to the requested operation's effective postconditions. Interrupted or timed-out remote operations have uncertain outcomes until reconciled. Revocation must remove live access; installation results must match runtime config; uninstall/purge results must reflect observed removal. Rollback/recovery failures must remain visible.

The [disposable harness](qa-test-plan.md#disposable-vps-integration-use-case) requires `running:true` for `wg0`, exact saved name/key membership and the same complete native `wg show wg0 peers` key set after each install/add/revoke/remove. Uninstall checks `uninstalled:true`, the exact requested `packagesPurged` Boolean, detect's config/tools state, actual config/symlink absence and native interface absence under available `/sys/class/net`. Purge additionally checks `wireguard`, `wireguard-tools` and `qrencode` as absent/not-installed through `dpkg-query`; residual `config-files` status or query failure fails. Keep-packages requires retained `wg` availability. Only fixed local stage/category/exit diagnostics are emitted, including malformed/nested JSON and cleanup failures. Offline injected controls establish these decisions; they establish no SSH, systemd, package or packet behavior. [Cleanup ownership and uncertain outcomes](operations.md#disposable-validation-and-recovery) remain explicit.

## Persistence and presentation

Detail's topology MTU and Interface field present the selected configuration's explicit MTU. Omitted/zero MTU or unavailable config displays `—`, independent of backend/state. This is configured data, not observed effective MTU: userspace supplies 1280 when omitted, while kernel tooling can derive a value from routes. The existing Backend API exposes no effective-MTU readback. Current-tunnel config notifications refresh Detail without a new load; selection/view ownership guards reject stale callbacks and clear unavailable values. No profile or backend policy changes.

Home's `VPN connected` label retains the existing recent-handshake aggregate heuristic; it does not prove routing, leak protection or all-peer health. The right-hand Endpoint value is the first configured peer's hostname from the first tunnel presented as active, without DNS resolution or public-IP discovery; absent data displays `—`. Home `LAST HANDSHAKE` adds a localized relative-age phrase to the newest positive observed peer timestamp, preserves `--` when missing and clamps future timestamps to the existing `0s` formatter result. Detail keeps the compact age without the phrase. The configured header count and preserved `Vpn0wn` wordmark add no backend state or identity migration.

Quick Settings membership is a nullable confirmation in the existing settings DataStore, independent of `TileService` creation, destruction and listening. `QuickTileService.onTileAdded` and native request results `TILE_ADDED`/`TILE_ALREADY_ADDED` persist true; `onTileRemoved` persists false. Missing pre-repair confirmation remains unknown, not proven absence. Writes use the application scope and existing serialized DataStore transactions, so normal activity/service teardown does not cancel them; app-process reconstruction retains committed values. Abrupt process termination before a write commits, persistence failure and notifications Android has not delivered remain outside that guarantee. Expected persistence failures retain prior data and log a fixed category without inventing an absent confirmation.

`UserKnobs` owns a process-local removal revision. Each native Add request and add notification captures that revision before asynchronous confirmation work; actual removal advances it synchronously before its false write is launched. A true confirmation checks the captured revision inside the DataStore transaction and skips its write after any later removal. Native request results and service notifications use independent callback channels, so a late successful/already-added result must not reassert membership after a genuine removal, including after Settings destruction. A new add notification/request captures the current revision and remains eligible. Process termination discards old callbacks; the revision needs no persistence or settings-format migration, while committed membership remains durable.

Android 13+ Settings keeps its Add tile row hidden until membership loads, then hides confirmed membership and offers the native idempotent fallback for false or a loaded value without recorded confirmation. A view-lifecycle observer applies later confirmations and removals while Settings stays open; stopping/recreating its view releases and reloads observation. An unavailable read keeps setup hidden until a later lifecycle observation loads confirmation; it never writes absence. Request cancellation and reported native errors do not record membership; existing visible Snackbar/background Toast feedback remains. Android versions below 13 still omit the setup action. No platform inventory query, new service or tunnel/backend behavior is added. [#85](https://github.com/novakin/vpn0wn-android/issues/85) owns independent native inventory/reopening acceptance.

`ObservableTunnel.statistics` is a cache-only bindable getter; it starts no backend work. Existing Home, Detail and TV pollers use nullable `getStatisticsAsync`, routed through `TunnelManager.getTunnelStatistics`. A fresh snapshot from the current backend/session is reused without copying or retimestamping; `Statistics.isStale` remains true only after more than 900ms. Equivalent stale/missing readers share one manager-owned in-flight request for the same managed tunnel identity, generation, backend instance and name. Admission uses the existing mutation lock briefly; backend IO and reader waits run outside it.

Before publishing on Main, the manager checks caller/application liveness, request identity, managed membership, UP state, generation, name and backend identity. DOWN/TOGGLE, reconnect, admitted config/rename/delete work and backend switching invalidate affected sessions. Cache reads reject a snapshot tagged with an earlier generation. TV clears and hides its transfer row when the result is unavailable.

Each reader owns its wait, not the shared request. Cancelling one reader preserves work needed by others; the last reader removes its request and cancels its shared read. Ordinary unavailable/obsolete sessions return null so still-active pollers can continue. A new request through an unmanaged tunnel retains `NotManagedException` rejection; an already-admitted read invalidated by deletion returns null. Owner invalidation is identified by its exact cancellation cause; genuine caller, application or backend cancellation propagates, as do backend failures and `Error`. Completed failures are not converted into obsolete success. Failed/cancelled requests can be retried. `runInterruptible` supports interruption of cooperative blocking Java work, not a guarantee that blocking JNI returns; native owners retain teardown responsibility.

These are the separately authorized [#48](https://github.com/novakin/vpn0wn-android/issues/48) source contracts. Its PR owns executed checks, review and delivery state. The [G2 investigation](reviews/2026-10-07-performance-source-investigation.md) preserves the original defect evidence. This source change establishes no physical VPN behavior or speed/battery gain.

Confirmed bulk deletion reuses the manager's serialized delete/rollback contract sequentially; cancellation stops remaining work after admitted settlement. Partial feedback reports observed removed/remaining snapshot members, and survivors remain selected. No persistence format, multi-peer/config parsing or backend transition policy changes. Corrupt-store warnings exclude payloads/parser causes. Protected SSH credential persistence remains separate.

`VpsDeployMapper` maps incomplete endpoint/CIDR to PROVISIONING. Complete records need a positive, nonfuture sync timestamp at most 600 seconds old: running true maps ONLINE, false OFFLINE and null ATTENTION. Missing, future or older timestamps map ATTENTION regardless of old running evidence. Recent-sync and running health checks express separate facts; stale running health is unknown.
